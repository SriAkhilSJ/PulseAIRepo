# CopilotKit verification — does the Pulse agent really render?

**Commit under test:** `14b8862b` — "Hermes-grade context/security + CopilotKit desktop fixed-right"
**Date:** 2026-08-29
**Verification method:** provider-free. Zero LLM/provider tokens were spent. Every
result below is reproducible without an API key.

## Short answer

**No — not on `14b8862b`.** The webview mounted, but the agent was unreachable and
the generative task card painted as an **empty white box**.

After the fixes in this branch the full path works: browser → Copilot Runtime →
Python LangGraph agent → A2UI card with real content and a live action button.
The run now proceeds through `task_manager` and stops only at the LLM call,
because no provider key is configured in this environment.

## What was verified, and how

Real DOM assertions were used rather than "the build succeeded". A jsdom +

with the real catalog and drives them with the exact A2UI operations the Python

`copilotkit.a2ui` from the committed schema).

```bash

```

## Findings

### 1. The A2UI task card rendered empty (root cause)

`src/a2ui_schemas/pulse_task_schema.json` used the **legacy props-nested** wire
format:

```json
{ "id": "root", "component": "Card", "props": { "child": "col" } }
```

A2UI **v0.9** expects props **flat**:

```json
{ "id": "root", "component": "Card", "child": "col" }
```

`@a2ui/web_core` v0.9 does `const { id, component, ...properties } = comp`
(`processing/message-processor.js:235`), so the legacy shape yields
`properties = { props: { child: "col" } }`. The generic binder then resolves
`{ props: {...} }`, so the renderer's `props.child` is `undefined`,
`children(props.child)` is never called, and the card paints empty.

**Measured** (`props-nested` vs `flat`, same catalog, same operations):

| schema shape | card text | buttons |
|---|---|---|
| props-nested (shipped) | `""` | 0 |
| flat v0.9 (fixed) | `"Fix bridge protocolIn progressRepair the stdio bridge handshakehighPulse AgentOpen in editor"` | 1 |

**Fix:** flattened `pulse_task_schema.json`. A regression test asserts no
component may contain a `props` key.

### 2. Runs never reached the Python agent

`pulse-webview/server.ts` combined a v1 `LangGraphHttpAgent` with
`CopilotKitIntelligence`. Every run was routed through CopilotKit Cloud:

```
GET /api/copilotkit/info  ->  "mode":"intelligence", "licenseStatus":"none"
POST .../agent/pulse_agent/run
  -> Failed to get or create thread: fetch failed
     host: 'api.intelligence.copilotkit.ai', port: 443
```

The Python agent on `:8123` received **nothing**. The app also hard-depended on
`INTELLIGENCE_API_KEY` (`apiKey: process.env.INTELLIGENCE_API_KEY!`).

**Fix:** the Python side is an **AG-UI** endpoint
(`add_langgraph_fastapi_endpoint`), so the runtime now uses an AG-UI
`HttpAgent`. `CopilotKitIntelligence` is optional and only enabled when
`INTELLIGENCE_API_KEY` is set.

```
mode: intelligence  ->  mode: sse (direct to agent)
```

### 3. The agent crashed on the first graph node

With correct wiring, runs reached `task_manager` and died:

```
KeyError: 'latest_instruction'     (chat_graph.py:1412)
KeyError: 'provider'               (chat_graph.py:2014, planner_node)
```

`latest_instruction` and the `provider`/`model` configurables are set by the
CLI/bridge entrypoints, **not** by any graph node. The AG-UI endpoint is driven
by a frontend that sends only `messages`, so both were missing.

**Fix:** `_latest_instruction_from_messages()` derives the instruction from the
trailing `HumanMessage`, and a `_cfg()` helper supplies settings-backed defaults
for `provider`/`model`. All 4 hard-index read sites converted; the 3 remaining
`configurable[...]` uses are writes and were left alone.

### 4. TypeScript build was broken

`npm run build` is `tsc -b && vite build`. `tsc -b` failed with **12 errors**:

- `App.tsx` passed `agent=` to `CopilotKitProvider` and `CopilotChat`; the v2 API
  has no such prop (`CopilotChat` uses `agentId`; the provider has none).
  The agent was therefore never bound client-side.
- zod duplication: the app used **zod 4.5.2** while `@copilotkit/a2ui-renderer`
  and `@a2ui/web_core` bundle **zod 3.25.76**. `GenericBinder` classifies props
  via `schema._def.typeName`, which is `undefined` on zod v4 — so dynamic
  bindings and actions silently degrade.

`vite build` still "passed" because esbuild strips types without checking them.

**Fix:** zod pinned to `3.25.76` (single deduped copy), `agentId` corrected,
provider-level `agent` prop removed. **`tsc -b`: 12 errors → 0.**

### 5. The card's action button was inert

`renderers.tsx` rendered `<button>` with no handler, ignoring the bound
`action`. Clicking it did nothing.

**Fix:** wired `onClick={props.action}` (the binder turns an `action`-shaped
prop into a callable). Now dispatches:

```json
{"userAction":{"name":"pulse_task_action","surfaceId":"pulse-task",
 "sourceComponentId":"action","context":{"taskId":"pulse-123"}}}
```

### 6. Preview could not reach the runtime

`App.tsx` hard-coded `runtimeUrl="http://localhost:8200/api/copilotkit"`, which
fails from any non-localhost origin (LAN, container, tunnel, preview).

**Fix:** relative `runtimeUrl="/api/copilotkit"` plus a Vite dev/preview proxy
to `:8200` (overridable via `COPILOT_RUNTIME_ORIGIN`). Verified:

```
GET /api/copilotkit/info  ->  200  {"mode":"sse","agents":["pulse_agent","default"],"a2ui":{"enabled":true}}
```

### 7. Runtime died on upstream socket close

A dropped agent connection raised an unhandled rejection that killed the
Node process, 502-ing the whole webview.

**Fix:** `unhandledRejection` / `uncaughtException` handlers log instead of
exiting.

## End-to-end evidence (after fixes)

Full stack live: Vite `:5173` → Copilot Runtime `:8200` → Python agent `:8123`.

```
$ curl -X POST /api/copilotkit/agent/pulse_agent/run -d '{"messages":[{"role":"user","content":"ping"}]}'
RUN_STARTED     threadId=verify-t5
STEP_STARTED    stepName=task_manager
STATE_SNAPSHOT  current_task="ping"  task_action="new"  task_status="in_progress"
RUN_ERROR       "terminated" / INCOMPLETE_STREAM
```

`task_manager` **completes successfully**. The run then reaches `ai_node` and
stops at:

```
groq.GroqError: The api_key client option must be set either by passing
api_key to the client or by setting the GROQ_API_KEY environment variable
```

That is the only remaining gap: **no LLM provider key is configured**. It is an
environment input, not a code defect.

## Running the stack

```bash
# 1. Python agent (:8123)
uv run python -m uvicorn src.server:app --host 0.0.0.0 --port 8123

# 2. Copilot Runtime (:8200)
cd pulse-webview && npm run runtime

# 3. Webview (:5173)
cd pulse-webview && npm run dev
```

Optionally set `INTELLIGENCE_API_KEY` to enable CopilotKit Intelligence; it is
no longer required.
