# Reference repositories rechecked against the continuous-run failure

**Date:** 2026-11-02. This is a source-code check, not a benchmark of the reference projects. Source links below are pinned to the inspected commits. The historical numbers in [the reference blueprint](ref_blueprints.html) describe reconstructed configurations at earlier revisions; they are not measured at the current heads and cannot be substituted for an apples-to-apples provider-token comparison.

## The Pulse evidence being explained

In [live run 41396088687](https://github.com/SriAkhilSJ/PulseAIRepo/actions/runs/41396088687), the parent received 67 tool definitions / 60,809 schema characters on requests 3–55, and provider input rose from 35,207 tokens at request 3 to 54,105 at request 55. Request 12 exposed an import failure (`NameError: api_logout`). The next 33 requests included 35 terminal starts and no write/edit start; those requests used 1,507,912 input tokens, some cached. The final artifact remained broken and incomplete. Details and limits: [root-cause analysis](CONTINUOUS_AGENT_ROOT_CAUSE_2026-11-02.md).

Continuous graph segmentation did pass an offline 75-cycle checkpoint test. That is progress on continuity, not proof of live delivery, lower token usage, or automatic recovery.

## 1. OpenCode: permission-filtered tools and cache-aware compaction

**Inspected:** `anomalyco/opencode` `ff90ed91607cabf420a369e9009539c1aa0932af` (`dev`); different from the historical blueprint's pin.

* **Tool surface:** The [session selects agent and session permissions before taking its tool snapshot](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/session/context.ts#L126-L151). The [snapshot excludes tools whose permissions are wholly denied, separates direct tools from Code Mode tools, sorts definitions, and exposes a Code Mode catalog](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/tool.ts#L250-L304). This is not proof that its default parent is always small: allowed plugins, catalog text, configuration, and tool descriptions still cost tokens. Measure the complete request, not just the number of direct schemas.
* **Context:** The [compaction implementation](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/session/compaction.ts#L43-L49) supports a reserve, a verbatim tail and optional background summary. Its comments [explicitly hold a background summary until compaction is due](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/session/compaction.ts#L105-L119), and describe preserving a cached prefix near the threshold ([lines 128–142](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/session/compaction.ts#L128-L142)). It uses graded clipping **to fit the transcript for the summarization request**; the source does not establish that every ordinary request is cheaply pruned at each of those levels.
* **Inspection:** The [read tool description](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/tool/plugin/read.ts#L21-L49) asks for larger reads rather than many tiny slices, and grep to locate content. That is guidance, not an enforcement mechanism that would necessarily catch Pulse's varied read loop.
* **Limits:** [Configured max steps disable tool choice](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/session/runner/llm.ts#L250-L271); the [max-steps message](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/session/runner/max-steps.ts#L1-L16) asks for text only. It is not evidence that other agents never stop at iteration limits.

**Adaptation for Pulse:** narrow the **actual parent** request to a stable task-relevant tool profile, with permission-preserving discovery for other capabilities; first measure schemas, catalog/discovery text, full serialized messages and cache outcomes. Separate compaction for window safety from an optional lower operating-context target for cumulative cost. Do not assume a near-window trigger would have fired in this run or claim the run had a cache-break bug without evidence.

## 2. OpenClaude: deferred discovery and preservation through compaction

**Inspected:** `Gitlawb/openclaude`, as identified by [the local audit](OPENCLAUDE_CONTEXT_MINUTE.md), now resolves through GitHub to `Twigpine/openclaude`; current head `87cbb5cba133a99b0d66f09e02ba8997d5012125`.

* [Tool search](https://github.com/Twigpine/openclaude/blob/87cbb5cba133a99b0d66f09e02ba8997d5012125/src/utils/toolSearch.ts#L156-L231) defers MCP/marked tools when enabled instead of always loading them inline. Auto mode uses a percentage threshold, with token-count API and fallback estimate ([lines 46–50, 97–143](https://github.com/Twigpine/openclaude/blob/87cbb5cba133a99b0d66f09e02ba8997d5012125/src/utils/toolSearch.ts#L46-L50)). Default, provider, model and proxy compatibility gates matter: this is not universally active ([lines 270–354](https://github.com/Twigpine/openclaude/blob/87cbb5cba133a99b0d66f09e02ba8997d5012125/src/utils/toolSearch.ts#L270-L354)).
* Its discovered-tool set is [carried over a compaction boundary](https://github.com/Twigpine/openclaude/blob/87cbb5cba133a99b0d66f09e02ba8997d5012125/src/utils/toolSearch.ts#L575-L623). This is the important integration detail: an optimization must not make already-discovered tools disappear after compaction or resume.
* It has [cache-break diagnostics](https://github.com/Twigpine/openclaude/blob/87cbb5cba133a99b0d66f09e02ba8997d5012125/src/services/api/promptCacheBreakDetection.ts) and a [repository-map implementation](https://github.com/Twigpine/openclaude/blob/87cbb5cba133a99b0d66f09e02ba8997d5012125/src/context/repoMap/index.ts); neither proves that those mechanisms would repair `api_logout` or that they caused a particular token saving in Pulse.

**Adaptation:** keep read/write/edit/terminal and applicable verification tools available; disclose other allowed capabilities through a searchable catalog. Persist activated tool identities across checkpoints and compaction, recheck authorization at execution, and make additions explicit for providers without native deferred-tool support. Catalog size and extra discovery round trips need measurement.

## 3. Hermes: named toolsets, bounded results, and structured command outcomes

**Inspected:** `NousResearch/hermes-agent` `edf1495a314f24745a65aeffd5f11b87da9ee595`.

* [Named toolsets include a coding posture](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/toolsets.py#L170-L190); [resolution](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/toolsets.py#L365-L405) expands included groups and registry contributions. Its [agent tool-surface function](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/toolsets.py#L469-L485) applies platform/side-agent exclusions. Configurable grouping is not a guarantee that every run uses the small coding profile.
* [Large tool results can be stored externally with a preview and retrievable path](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/tools/tool_result_storage.py#L366-L435); [turn-level output budgeting](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/tools/tool_result_storage.py#L461-L470) is separate. Its [proactive pruning](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/agent/context_compressor_prune.py#L28-L69) deduplicates identical results, protects a recent tail for other passes, and has persistence safeguards. Even exact deduplication alone cannot detect all the different overlapping reads seen in Pulse.
* Its terminal outcome includes [output, exit code, optional interpretation and verification evidence](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/tools/terminal_tool_result.py#L196-L203) ([result assembly](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/tools/terminal_tool_result.py#L245-L270)). It distinguishes expected non-zero statuses like grep no-match from errors ([lines 74–115](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/tools/terminal_tool_result.py#L74-L115)). This shows error-aware feedback; it does **not** establish that an arbitrary failed import is persisted as actionable debt until fixed.
* **Limits:** Its [budget implementation](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/agent/iteration_budget.py#L1-L7) documents default parent/subagent caps of 500/50, and [the turn loop stops when consumption fails](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/agent/turn_iteration_prep.py#L406-L416). A warning may ask the model to checkpoint and continue before that; it does not override the hard budget.

**Adaptation:** apply a parent profile at the real binding seam; preserve full evidence securely when showing a bounded preview; classify command-specific status rather than treating all non-zero exits alike. Add revision-aware current startup failures separately from permanent stable-check debt—this is our proposed design, not a verified Hermes feature.

## 4. Aider: compact code navigation and failure-to-repair feedback

**Inspected:** `Aider-AI/aider` `5dc9490bb35f9729ef2c95d00a19ccd30c26339c`.

* Its [ranked repository map](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/repomap.py#L43-L70) defaults to a 1,024-token target, [expanded when no files are in chat](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/repomap.py#L120-L132). That map is conditional and may be disabled; 1,024 is a target, not a universal per-request provider measurement.
* After an edit, [lint and test failures can become the next model message](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/coders/base_coder.py#L1596-L1623), subject to configured auto-lint/auto-test and confirmation. Defaults in the class are [auto-lint on, auto-test off](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/coders/base_coder.py#L95-L107); reflection retries [stop after three](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/coders/base_coder.py#L923-L946).
* Its [SEARCH/REPLACE parser reports malformed/unmatched edits](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/coders/editblock_coder.py#L196-L217). These are mechanisms for focused edits and feedback, not proof that text diffs are always cheaper or more reliable than native tools for Pulse.

**Adaptation:** turn a failed startup/import probe into concise, revision-scoped repair context, including command, error and relevant file; after a change, rerun or mark stale appropriately. Feed real verification failures back without declaring completion and without imposing Aider's three-retry hard stop on productive continuous work. A repo map may help navigation, but assess its own added token cost and freshness.

## 5. Void: conditional tool assembly, structured edits, bounded terminal output

**Inspected:** `voideditor/void` `b3166e7ef2aefbdfeb139445fdf248a561b85d4d`.

* [Tool selection depends on chat mode](https://github.com/voideditor/void/blob/b3166e7ef2aefbdfeb139445fdf248a561b85d4d/src/vs/workbench/contrib/void/common/prompt/prompts.ts#L361-L377); agent mode includes built-ins and available MCP tools. [XML tool text is assembled from those selected tools](https://github.com/voideditor/void/blob/b3166e7ef2aefbdfeb139445fdf248a561b85d4d/src/vs/workbench/contrib/void/common/prompt/prompts.ts#L380-L409). This is mode gating, **not** proof of task-aware per-turn schema narrowing in agent mode.
* The [prompt specifies SEARCH/REPLACE constraints](https://github.com/voideditor/void/blob/b3166e7ef2aefbdfeb139445fdf248a561b85d4d/src/vs/workbench/contrib/void/common/prompt/prompts.ts#L111-L125), and its [terminal service clips large output head/tail](https://github.com/voideditor/void/blob/b3166e7ef2aefbdfeb139445fdf248a561b85d4d/src/vs/workbench/contrib/void/browser/terminalToolService.ts#L364-L374). The constants include a [20,000-character initial directory-tree cap and 100,000-character terminal cap](https://github.com/voideditor/void/blob/b3166e7ef2aefbdfeb139445fdf248a561b85d4d/src/vs/workbench/contrib/void/common/prompt/prompts.ts#L19-L29). Limits are not evidence that those specific values are appropriate for Pulse.

**Adaptation:** mode-aware exposure and bounded output are relevant; do not blindly switch the provider to XML or copy the old Void token estimate, which may double count tool text. Output clipping must retain error details and allow authorized access to full output when needed.

## 6. OpenHands SDK: stuck patterns and explicit stop semantics

**Inspected:** `OpenHands/software-agent-sdk` `98849457621881ae2414719b82b8bc1cf535b4ab`. The current `OpenHands/OpenHands` app repository is at `172d7f180096cfe06f1a875d2fcbbcb1fae2b6bb`; the relevant agent runtime implementation was checked in the separate SDK repository, not inferred from the app tree.

* The [stuck detector](https://github.com/OpenHands/software-agent-sdk/blob/98849457621881ae2414719b82b8bc1cf535b4ab/openhands-sdk/openhands/sdk/conversation/stuck_detector.py#L27-L35) recognizes identical action/observation, repeated action/error, monologue and alternating patterns. It [compares action and observation content while ignoring event IDs](https://github.com/OpenHands/software-agent-sdk/blob/98849457621881ae2414719b82b8bc1cf535b4ab/openhands-sdk/openhands/sdk/conversation/stuck_detector.py#L465-L503); changing line ranges and results can still evade exact equality. An [action-error nudge](https://github.com/OpenHands/software-agent-sdk/blob/98849457621881ae2414719b82b8bc1cf535b4ab/openhands-sdk/openhands/sdk/conversation/stuck_detector.py#L333-L381) arrives before the repeated-error threshold triggers stuck detection.
* [The local conversation actually marks `STUCK` and stops](https://github.com/OpenHands/software-agent-sdk/blob/98849457621881ae2414719b82b8bc1cf535b4ab/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py#L787-L808), so copying its behavior verbatim conflicts with the user's preference for continued productive execution. A warning followed by a change of strategy is the useful idea; do not assume its detector solves semantic repetition.
* Its [LLM condenser](https://github.com/OpenHands/software-agent-sdk/blob/98849457621881ae2414719b82b8bc1cf535b4ab/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L55-L77) has event and token thresholds and preserves an initial prefix; [token pressure is hard and event-count pressure soft](https://github.com/OpenHands/software-agent-sdk/blob/98849457621881ae2414719b82b8bc1cf535b4ab/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L158-L203). This is a configurable history-management mechanism, not proof it would trigger early enough or reduce total billed tokens for our run.

**Adaptation:** detect repeated *families* of inspection against the same repository revision and overlapping files/ranges, track recent real progress separately, then give an actionable non-blocking strategy nudge. Reset or decay on meaningful change. Read-only tasks, legitimate large-file pagination, external searches and concurrent execution need false-positive tests. No automatic edits or forced completion.

## Concrete implementation and verification order for Pulse

1. **Parent provider boundary:** trace `_resolve_bound_tools` in `src/graphs/chat_graph.py` through `src/tools/toolsets.py`, permissions, provider binding, delegation, tool-call dispatch and resume. Add a stable task profile and authorized discovery, not just a resolver-only unit test. Integration test the actual bound parent payload and ensure needed tools remain discoverable; verify denied tools cannot be executed.
2. **Actionable repair state:** trace terminal result → `src/graphs/gates.py` → graph state → prompt construction → checkpoint → verification. Preserve a bounded current `NameError` startup signal associated with the relevant command/files/revision; clear on successful equivalent check, supersede/stale on changes, and never let irrelevant exploratory failures create permanent debt. Replay the captured case offline.
3. **Progress nudge:** trace `src/graphs/progress_helpers.py` and call sites. Add a bounded revision-aware sliding window for overlapping inspections and absent writes/verification; emit an advisory with evidence and options, not an iteration cap. Test legitimate read-heavy work and pause/cancellation/permissions.
4. **Context and telemetry:** trace `src/context/compaction.py` through request preparation, checkpoints and `src/llm/factory.py`. Measure full serialized tool calls and schema bytes, provider input/cache usage, compaction cost, and per-request latency. Test tool-call/result pairing, current failure preservation and cache behavior; use a cost-aware operating threshold independently from provider-window safety. Do not claim fewer tokens until measured.
5. **Controlled evaluation:** replay the same history offline for identical logical tool availability and budget, then run an explicitly approved same-model, same-provider, same-prompt/settings A/B with both **per-request overhead** and **total tokens/time to verified outcome**, including cache and compaction costs. A smaller schema must not hide missing tools or lower completion quality. Preserve explicit budget, cancellation and side-effect safety.

None of these five fixes is implemented by this reference recheck. No paid provider benchmark was run for it.
