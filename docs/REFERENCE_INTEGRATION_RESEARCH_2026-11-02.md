# Reference research and integration-risk map (research only)

## Scope and method

This follows the [source-pinned reference recheck](REFERENCE_REPOS_RECHECK_2026-11-02.md), the two blueprint HTML files and [live-run root cause](CONTINUOUS_AGENT_ROOT_CAUSE_2026-11-02.md). I traced the relevant provider, tool, progress, verification, context and checkpoint code paths and their nearby tests in Pulse, then inspected the corresponding current source files in the reference repositories. This is **not a review of every file** in these large repositories, a proof that the code cannot break, or a benchmark of the reference repos. No application code was changed. Reference commit hashes are pinned in the earlier recheck and in the source links below.

## New findings: what a change must not overlook

### 1. There are multiple progress/revision systems—not one

**Actual pipeline:** `SafeToolNode` / durable batch → `src/runtime/tool_middleware.py` → `src/graphs/progress_guard.py` with `src/runtime/run_state_ledger.py` → tool result → `src/graphs/chat_graph.py::progress_node` with `src/graphs/progress_helpers.py` → `after_progress`.

* The middleware calls `evaluate_operation_progress` **before** execution and appends an advisory to the tool result **after** execution. This is advisory, not a pre-execution block ([middleware](../src/runtime/tool_middleware.py#L214-L280)).
* Its process-local `AgentRunState` is obtained from a module-level dictionary ([ledger registry](../src/runtime/run_state_ledger.py#L137-L145)). The docstring says persistent, but the shown registry does not itself persist across a process restart. It is distinct from `AgentState.workspace_revision` persisted by LangGraph; don't assume they are synchronized.
* Middleware marks any successful `terminal` or `execute_code` call as a mutation, and marks nonempty output not starting `Error` as new information ([recording](../src/runtime/tool_middleware.py#L282-L294)). Therefore even a successful shell read can advance that ledger revision, and repeating the same nonempty output resets its no-progress counter. This follows from the code; the captured live run does not expose this ledger's state, so it is **not proven** to be the sole reason the live run stalled. `run_terminal` and `terminal` do not receive identical mutation treatment in this expression.
* The existing inspection-sprawl check only recognizes `search_files`, `read_file`, `list_files`, `execute_code`—not `terminal` or `run_terminal`—and only after its ledger revision is at least 2 ([guard](../src/graphs/progress_guard.py#L72-L95)). Its guidance specifically demands a server/frontend, which is inappropriate for many tasks and read-only research. This is existing behavior, not a proposed general solution.
* The graph's separate [progress node](../src/graphs/chat_graph.py#L5332-L5445) maintains its own revision/mutation ledger using file-tool names and shell regexes; document edits and arbitrary script writes have different treatment. Do not call either revision a fully reliable filesystem change detector without further tests.
* There is also an exact trailing-cycle guard: it hashes full names, args, outcomes and results, warns at 3 repetitions and hard-stops at 5 ([helper](../src/graphs/progress_helpers.py#L395-L507); [routing](../src/graphs/chat_graph.py#L5575-L5634); [stop](../src/graphs/chat_graph.py#L5718-L5723)). The hard-stop path is a truthful failure, but it is a separate stopping condition that the previous continuity change did not remove. No such marker appeared in the captured live run. Avoid claiming the system has *no* progress guards.

**Reference comparison:** OpenHands checks exact/alternating actions and outcomes and can stop a stuck run; its [validation-error nudge matches parallel errors to call IDs and avoids counting calls in the same unseen response as multiple retry rounds](https://github.com/OpenHands/software-agent-sdk/blob/98849457621881ae2414719b82b8bc1cf535b4ab/openhands-sdk/openhands/sdk/conversation/stuck_detector.py#L195-L307). Hermes persists a proposed tool-call turn before executing side effects and [stops if persistence fails](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/agent/turn_tool_round.py#L130-L153). Neither is proof of a reliable semantic-overlap detector. A revision-aware advisory in Pulse is still a proposal.

**Safe research direction:** unify or explicitly reconcile these sources before using revision as a signal; treat ambiguous shell commands as *unknown*, not safely read-only. Use bounded, privacy-safe observations and avoid server-specific nudges. Genuine information gain, successful verification, work in non-file tools, browsing, read-only tasks and user-directed multi-page reads must not be called stagnation just because no edit occurred. Preserve durable side-effect deduplication and cancellation.

### 2. Binding a smaller parent list does not automatically enforce that list

`src/graphs/chat_graph.py::_resolve_bound_tools` starts with the global registry, applies availability checks, strict-child filtering and state-derived phases, then `ai_node` binds the result ([binding](../src/graphs/chat_graph.py#L1594-L1666); [model bind](../src/graphs/chat_graph.py#L2183-L2189)). Some retries/failovers bind again. The pre-delivery phase can restrict an empty autonomous workspace to `write_file`; after a file lands the normal parent can have a much broader set, matching this run's 1→67 observations.

The `SafeToolNode` has its own full `_tools_by_name` registry. `_resolve_bound_tools` writes `phase_allowed_tools` only when a non-neutral phase has an allowlist ([phase setting](../src/graphs/chat_graph.py#L1888-L1900)); the executor [checks that allowlist before permissions](../src/graphs/chat_graph.py#L6598-L6630). In a neutral phase it is `None`. Therefore hiding a schema in the provider request is **not by itself** an execution-time authorization guarantee. This is an integration/security requirement to test, not a claim that a particular denied tool was exploited in the benchmark. Canonicalize aliases *before* checks; retain existing `SafetyGuard`, approvals and durable journaling.

`resolve_runtime_tool_names` maps capability profiles to tool groups ([toolsets](../src/tools/toolsets.py#L102-L139)), but it can omit capabilities based on task classification. Pulse's own [execution phase rationale](../src/runtime/execution_phases.py#L1-L14) records an earlier regression where word-based narrowing removed browser tools. A simple top-N cap or keyword-only gate may therefore repeat the old failure. Existing [child-scope test](../src/tests/test_subagent_scoped_binding.py#L67-L72) deliberately expects the current broad parent; changing the contract requires updating it with stronger tests, not silently deleting it.

**Reference comparison:** OpenCode [merges permissions before taking the tool snapshot](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/session/context.ts#L126-L151), then its [Code Mode inventory separates direct and catalog tools](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/tool.ts#L250-L304); [catalog change messages](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/codemode/instructions.ts#L11-L17) explicitly say when discovery is needed. Hermes has a provider-agnostic [search/describe/call bridge](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/tools/tool_search.py#L1-L7), a [bounded catalog](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/tools/tool_search_catalog.py#L265-L298), and [session availability validation](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/tools/tool_search.py#L579-L615). Its source notes a real tradeoff: deferring `clarify` reduced its use in its own A/B ([source comment](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/tools/tool_search.py#L138-L147)); that is their result, not our benchmark.

**Safe research direction:** establish the intersection of permitted, phase-allowed, actually advertised/discovered and currently available capabilities as an explicit runtime contract. Design a discovery route that does not grant new authority and works on the selected provider. Test MCP changes, delegated strict scopes, ask/plan/no-change modes, browser installation, multi-call batches, tool-name repair, retries, resume and failover. Do not substitute command execution / Code Mode for permissions or increase shell privileges merely to reduce schemas. Include catalog and extra-call overhead in the measurement.

### 3. Failure telemetry, verification debt and repair guidance are separate channels

**Actual path:** foreground terminal captures output and exit status → `src/tools/terminal_tools.py::_record_verification_result` calls `services.verification.record_command` in `src/context/verification_evidence.py` → `src/runtime/verification_events.py` journals/project events. Independently, `progress_node` stores a classified trace and failure in `AgentState`; `src/graphs/gates.py::_unresolved_failed_verification_checks` computes *durable stable-check debt* from that trace. Finally `_resolve_bound_tools` can enter repair/recheck phases, while the finish gate evaluates required evidence.

The stable debt classifier [deliberately excludes ad-hoc probes](../src/graphs/gates.py#L477-L525): a prior case made a disposable failed `python -c` probe a permanent obligation even after real tests passed. For the live `api_logout` import, this narrowness means no stable-check debt; it does **not** mean the raw error was never returned or that all verification systems ignored it. The final state had `unresolved_check_debts=0` while the overall run remained correctly unverified. Do not fix this by adding every failed shell command to permanent debt.

The stable-debt phases are **structural**: before repair, terminal/check tools can be removed; after a landed edit, file mutation can be removed until the same check reruns ([repair/recheck phases](../src/graphs/chat_graph.py#L1818-L1852); [tests](../src/tests/test_attempt11_product_delivery_boundary.py#L235-L287)). Adding transient probes to that same path could unintentionally disable the very tool needed to investigate or unblock an environment issue. A successful weaker check must not erase a failed required suite; later code changes can also make earlier green results stale.

**Reference comparison:** Aider passes lint/test errors into a reflection only after a configured check and confirmation; test automation is not always on ([source](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/coders/base_coder.py#L1596-L1623)). Hermes' [verification classifier](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/agent/verification_evidence.py#L551-L596) uses detected canonical commands and treats ad-hoc verification specially; it can use pipeline status to avoid treating a succeeding filter as proof that the verifier succeeded. It is more nuanced than interpreting every `exit 0` as proof. We have not proven that it would promote the exact `api_logout` probe to a persistent repair obligation.

**Safe research direction:** a separate bounded *actionable observation* could preserve the command, relevant file/error, workspace/turn identity and evidence age without changing existing permanent-debt semantics. Define when it is resolved, superseded, stale, irrelevant or user-dismissed. Don't use arbitrary inferred file mappings as truth; preserve evidence through summaries and status without equating an observation with verification. Cover nonzero commands with expected meanings, shell pipelines, errors from missing dependencies, changed files, unrelated green tests, and privacy/redaction.

### 4. Pre-send deduplication has a reproducible tool-pairing hazard

`src/llm/request_sanitizer.py` currently deduplicates byte-identical results by dropping the older result and **rewiring** the earlier assistant call ID to the newer ID. A provider-free reproduction with two successive `read_file` calls `c1` and `c2` and identical results yielded:

```
assistant: read_file(path=a), id=c2
assistant: read_file(path=b), id=c2
tool:      id=c2, content='same'
```

The earlier assistant call now has no immediately following matching tool result; the same ID is used by two calls. The current test [asserts the rewire](../src/tests/test_request_sanitizer.py#L69-L85) rather than verifying positional one-call/one-result consistency. `_pair_tool_calls_positionally` [only checks whether an ID appears anywhere](../src/llm/request_sanitizer.py#L328-L365), despite its name. Strict-provider rejection is a **risk**, not an observed provider rejection in this reproduction or a claimed cause of the live failure. This needs investigation before more aggressive result compression/dedup is introduced.

Hermes' documented prune [keeps the newest full result and replaces earlier duplicate result bodies with references](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/agent/context_compressor_prune.py#L40-L48); its in-place rewrite preserves row order/count ([lines 137–152](https://github.com/NousResearch/hermes-agent/blob/edf1495a314f24745a65aeffd5f11b87da9ee595/agent/context_compressor_prune.py#L137-L152)). That pattern suggests retaining each call/result identity while shortening duplicate content, subject to provider-specific validation. Don't copy a code path without checking complete protocol semantics, multimodal data, cross-session access, and persistence failure behavior.

### 5. Pulse already does some context reduction—don’t add a second competing pipeline blindly

`ContextEngine.build_ai_messages` allocates a history budget, runs `HistoryShaper` and assembles stable/volatile context ([engine](../src/context/context_engine.py#L1613-L1690); [shaper](../src/context/history_shaper.py)). `HistoryCompactor.compact` applies landed mutation-argument reduction and a per-tool summarizer even when history fits; it escalates to prune, clipping and finally structural compaction if needed ([pipeline](../src/context/compaction.py#L860-L935)). This is a meaningful existing improvement. The main compaction path operates on a request-only copy; the checkpoint remains the source of history. `micro_compaction.py` is a separate opt-in mechanism, not evidence it was active in the live run.

The code comment that masking keeps a prefix byte-stable should be validated per actual message/prefix: changing an earlier result's text still changes bytes at that position, even if message indices remain stable. The captured run had no recorded active compaction markers, not proof that no per-tool summarization/argument omission occurred. The window was very large relative to the observed 35k–54k input, so ordinary window pressure may never fire.

**Reference comparison:** OpenCode holds a [background summary until the auto threshold](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/session/compaction.ts#L105-L119) to avoid premature prefix churn; its history rebuilds a [settled suffix and preserved recent messages](https://github.com/anomalyco/opencode/blob/ff90ed91607cabf420a369e9009539c1aa0932af/packages/core/src/session/history.ts#L219-L256). OpenClaude [carries discovered tools through compaction](https://github.com/Twigpine/openclaude/blob/87cbb5cba133a99b0d66f09e02ba8997d5012125/src/utils/toolSearch.ts#L575-L623) and can stop after repeated compaction failures rather than retry forever ([query](https://github.com/Twigpine/openclaude/blob/87cbb5cba133a99b0d66f09e02ba8997d5012125/src/query.ts#L1428-L1495)). This is a safety stop, not a promise of uninterrupted task completion.

**Safe research direction:** first measure existing request construction after `RetryLLMProxy` sanitization/trimming, including tool arguments—not just `message_chars` ([snapshot](../src/llm/factory.py#L236-L285)). Compare quality, provider-cached/uncached tokens, summarizer tokens and latency. Any new earlier compaction target must preserve user intent, current errors, tool-call/result pairs, discovered capabilities, active approvals and checkpoint-resume safety; validate whether it actually improves cost under the provider's cache pricing.

## Cross-file contract checklist for future work

| Contract | Files that must be traced together | Regression to prevent |
|---|---|---|
| Parent tool visibility | `chat_graph.py`, `tools/toolsets.py`, `agents/runtime_profile.py`, `runtime/execution_phases.py`, `llm/factory.py` | Task wording hides essential browser, verification, or delivery tools; payload measurements report resolver output instead of wire payload. |
| Actual authorization | `SafeToolNode`, `runtime/permissions*`, safety guard, phase config, `parallel_tools.py`, MCP/delegation | Unadvertised or discovered tool becomes executable without checking current scope/approval; alias bypass; mixed batch partially executes unexpectedly. |
| Call durability | `runtime/tool_middleware.py`, journal/persistence, `parallel_tools.py`, `graphs/continuous_execution.py`, both graph entry points | Resume duplicates a side effect or skips a result; a missing durable result is mistaken for safe retry. |
| Progress | `progress_guard.py`, `run_state_ledger.py`, `progress_helpers.py`, `chat_graph.py`, `state.py`, turn reset and UI status events | Successful inspections falsely reset counters, useful read-only work is blocked, or old guard state contaminates a new turn. |
| Evidence & completion | `terminal_tools.py`, `context/verification_evidence.py`, `runtime/verification_events.py`, `graphs/gates.py`, `chat_graph.py`, `runtime/status_contract.py` | A transient probe becomes permanent debt, a green weaker check masks a red required suite, or stale results become verified completion. |
| Context & protocol | `context_engine.py`, `history_shaper.py`, `compaction.py`, `micro_compaction.py`, `llm/request_sanitizer.py`, `llm/factory.py` | Error/call/result/intent disappears; duplicated IDs invalidate requests; context savings increase cache or summary costs. |
| Cancellation/budgets | `runtime/turn_control.py`, `graphs/budget.py`, `continuous_execution.py`, bridge and `SafeToolNode` | Any attempt to avoid iteration stops bypasses explicit budgets, approval, cancellation, or replays uncertain side effects. |

This checklist is an inspection scope, not a claim all possible downstream files have been audited. Before implementation, inventory direct call sites, protocol consumers, configuration/feature flags and regression tests for each concrete design.

* The tests wrote local performance diagnostic files as a side effect; those test-created changes were reverted/removed. The research documents are the only intended workspace changes.
* Existing live evidence remains: requests 3–55 sent 67 tool schemas; requests 13–45 consumed 1,507,912 provider input tokens and included no write/edit starts; run ended incomplete. These are historical observations, not a new comparison.

## Recommended next step—still research, not implementation

Choose and review the design contracts above, starting with (1) actual allowed/discoverable/executable tool identity, (2) call/result pairing, (3) authoritative revision/evidence semantics, and only then (4) optional progress and operating-context policies. Establish provider-free end-to-end reproductions at the real graph and adapter boundaries before proposing code. Once implementation is explicitly requested, run the relevant cross-file tests and an explicitly approved controlled benchmark. No token or latency improvement can be claimed before that.
