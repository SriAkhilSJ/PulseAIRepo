## Sequence observed (approve)

```
session_info / workspace.bound / turn_started
turn_lifecycle APPROVAL_AND_PERMISSION_CHECK
plan_updated ...
safety_request   tool_id=orch-…  name=write_file
                 arguments={path: notes.md, operation: CREATE,
                            node_id: task_notes, task_id: turn_…,
                            workspace: <disposable>}
                 warning="DOCUMENTATION notes.md: notes"
session_info     cancel_requested=false   (queue acknowledge is internal)
<desktop/consumer safety_reply approved=true, same session_id, same tool_id>
turn_lifecycle ...
safety_request   tool_id=orch-…  arguments={path: src/req_001_module.py, …}
<safety_reply approved=true>
turn_lifecycle IMPLEMENTATION … FINAL_DELIVERY
turn_done        completed=true
```

The request is published with `event_bus.emit("tool.approval.request", …)` and
projected by the bridge to Protocol v2 `safety_request`; the reply is the
existing `safety_reply` handler resolving the shared `ApprovalQueue` with
`session_id`.

## Deterministic unit/integration tests

`src/tests/test_orchestrator_approval_integration.py` — **9 passed**:

- request published with task/session/workspace/resource/operation fields;
- approve issues an `APPV-` token that the risk gate verifies;
- denial, timeout and turn cancellation raise `ApprovalDenied`, no token;
- wrong-session reply refused; duplicate/stale reply refused;
- token for `product.json` does not authorize `notes.md` (and vice versa);
- `workspace_session` low-risk path stays silent, high risk still asks;
- broker integration: approved token modifies `product.json`; denial leaves it
  byte-identical; the same token cannot be reused.

## Code paths

`ApprovalQueue.resolve()` now refuses non-pending requests, so a duplicate or
late reply returns `False` instead of re-applying a verdict.
`ApprovalQueue.wait_for_decision()` gained `should_stop`, polled at 100 ms, so a
turn Stop wakes an outstanding approval instead of waiting forever.
